## 〇.一 整体思路：直播是怎么运转的？

**如果你是第一次接触直播、只想快速搞懂大框架的同学，读这一节就够了。** 这一节不讲具体操作步骤，只讲整条直播链路是怎么串起来的。

### 一句话概括

> 相机负责「拍」，OBS Studio〔2〕负责「切」，SRS〔1〕负责「转」，网线和路由器负责「传」，直播平台负责「播」。

### 两个环节

**第一步：在本地搭一条"内部通道"**

把所有相机都接到一台笔记本电脑上：USB 线直接连，或者通过采集卡连。这台电脑上运行 OBS Studio，负责看清每个机位的画面、切换镜头、加字幕或台标。接着，OBS 把"切好"的画面**推流**〔3〕给 SRS 服务器——SRS 是一台专门用来接收和转播视频流的软件，它运行在你自己的一台电脑上。到这一步为止，所有设备都在同一个局域网〔6〕里，通过路由器互通，还没有上网。

**第二步：把画面送上互联网**

SRS 把画面接收下来之后，需要想办法"送上网"。这一步有一个关键的差别：

- **报告厅（教学主楼 A）**：有互联网。SRS 直接把画面推给直播平台（微信视频号、B 站等）就行，一步到位。
- **操场**：主席台的电脑上不了外网，但它和宿舍、教学楼同属一个校园网。所以需要一台放在宿舍里的电脑，先把画面从操场 SRS 里**拉流**〔4〕出来，再重新**推流**到直播平台。这个"借宿舍电脑转一手"的过程，就叫**二次转发**〔5〕。

## 一.直播的原理

1. 整场直播的基本流程是：先用 SRS 软件在你自己的电脑上搭一个直播服务器，再用 OBS Studio 负责切换画面，最后把画面推送到 SRS 服务器统一分发。

2. **操场直播**：操场主席台的电脑没法直接连上互联网，但它跟学校其他区域（比如宿舍，教学楼 4 号楼、行政楼除外）在同一个校园网里。所以直播信号要先经过校园网，借宿舍等区域的一台电脑做**二次转发**（先拉流、再推流），才能最终送到互联网上。

3. **报告厅直播**：教学主楼 A 报告厅可以直接连接互联网，所以用 OBS Studio 直接往外推流就行，不需要二次转发。

## 二.直播的准备

### 一般性准备

1. **相机一台**：建议关掉自动对焦，改成手动对焦（MF）〔9〕，把焦点固定锁在舞台上，防止镜头抽搐或突然跑焦。

2. **假电池一块**：相机自带电池撑不了几小时，原则上要准备一块**假电池**〔10〕（一种外形像电池、实际是外接电源适配器的配件），保证长时间录制不断电。不过实测发现，唯卓仕的 FZ100 电池支持通过 micro-USB 接口持续供电，效果和假电池一样。因此**索尼 α1、α7III、α7IV、α7RIII、α7RⅣ、α7RV、α9、α9II、α9III、α6600、α6700、α7SIII、FX3、FX2 等机型**的用户直接买唯卓仕电池充电供电即可。**佳能用户注意：必须合上电池仓盖，相机才能开机。**

3. **笔记本电脑不少于 1 台**：原则上建议用**单显卡**〔11〕的笔记本电脑（比如普通全能本〔13〕、MacBook）。如果电脑是双显卡，但支持**独显直连**〔12〕，或者能通过省电模式关掉独立显卡，也可以使用。为什么对显卡这么挑？因为双显卡在接收视频流时容易出兼容性 Bug，详见【常见问题 2】。

```
如果有不止一台笔记本电脑，请阅读以下说明：

1. 用于直播画面切换 / 在宿舍进行直播画面转发的笔记本电脑，
   必须是单显卡、支持显卡直连、或支持关闭独立显卡的机型。

2. 安装 SRS 的笔记本电脑应具备千兆或万兆网口〔14〕以保证网速，
   并拥有较强的 CPU 性能（因为要同时处理大量视频数据）。
```

4. **三脚架一台**：越高越好（2024 年末迎新晚会用了一台 2.2 米高的三脚架）。

5. **路由器一台**：校区有一台小米 AX3000T 路由器，如需借用，请联系时任招生办公室助理团淮安新媒体部部长。

6. **操场直播专用**：准备足够长的插线板和网线（校区现有一根 30 米绿联 CAT-5e 网线、2 根 20 米插线板，可向部长借用）。

### 特殊性准备

1. **APS-C 画幅〔15〕微单相机容易过热**：建议提前一天做一次持续性压力测试〔19〕（连续录制较长时间），防止直播中途机身过热自动关机。可以通过贴退热贴、加散热背夹等方式延长录制时间。一般来说，如果走 USB 接口输出视频，即使是索尼 α6700 也不会过热；但如果用**采集卡**〔16〕输出，务必提前做压力测试。

2. **USB 输出画质偏低**：USB 接口输出的画面质量普遍不如 HDMI〔17〕。所以对于带 HDMI 或 micro-USB 接口的相机，建议用「采集卡 + HDMI 线」把相机和笔记本电脑连起来，并在相机机内设置输出全尺寸 4K〔18〕画面。

3. **多机位**：DJI OSMO Pocket3、DJI Mavic Air3 等设备都可以作为额外的机位参与直播。

4. **收音（重要）**：推荐用 DJI Mic（第二代）获取更高质量的声音。不过要注意：2024 年 10 月迎新晚会上，由于舞台到直播机位距离较远，DJI Mic（第二代）出现过信号断联的故障。距离远时要提前踩点测试。

5. **多平台同时直播**：如果需要把画面同时推到多个平台，请安装兼容 OBS 的多路推流插件〔40〕。

### 直播前你应该做的

0. **（可选）安装 ffmpeg**〔32〕：下载并解压 ffmpeg，把它的 bin 目录添加到系统环境变量〔20〕。

`https://ffmpeg.org/`

## 三.直播的配置

下面按照操作顺序，一步一步来。**每一小步做完再进下一步，不要跳。**

### 第一步：启动 SRS

用**管理员权限**〔39〕打开 SRS 客户端（右键 → 以管理员身份运行），之后全程保持它在后台运行，千万不要关。（再次提醒：装 SRS 的电脑要千兆/万兆网口 + 较强 CPU；操场直播时这台电脑建议就放在操场；一般推荐 Windows 系统。）

![srs_software](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic3.png?raw=true)

### 第二步：登录路由器后台

打开浏览器，输入 SRS 电脑所连接路由器的登录地址。小米路由器默认是 `192.168.31.1`；其他品牌请看机身背面的标签。本文以刷了 OpenWRT〔23〕系统的小米路由器为例，界面和官方系统不太一样，但设置原理完全相同。

### 第三步：记住路由器和电脑的 IP 地址

1. 先在路由器后台里找到这台路由器的 IP 地址，记下来，后面很重要。

![ip](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic4.png?raw=true)

2. 再看电脑自己的 IP〔8〕：Windows 下同时按 `Win 键 + R`，输入 `cmd` 回车，在命令提示符里输入 `ipconfig`，找到"IPv4 地址"。它的前 3 位和路由器登录地址一致（小米路由器通常就是 `192.168.31.*`）。

![ipconfig](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic5.png?raw=true)

### 第四步：开启端口转发 / DMZ（让外网能找到 SRS）

进入路由器后台的「高级设置 / 防火墙」→「端口转发」。创建一条规则，把装有 SRS 的那台电脑的 IP 设为内网 IP 进行映射，这就是**端口转发**〔25〕。**如果没有什么特殊需求，直接开启 DMZ**〔26〕**（转发全部端口）最省事。** 其余设置保持默认即可。

![dmz](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic6.png?raw=true)

### 第五步：给直播机位编号

提前把编号写在纸上，贴在负责画面切换的笔记本前，直播时不慌乱。例如 2024 年迎新晚会用过：

```
1. ILCE-6700   编号：01
2. DJI Mavic Air3   编号：02
3. DJI Mavic Air2   编号：03
4. DJI Osmo Pocket3   编号：04
5. Canon Eos R8   编号：05
```

另外还要给以下两类画面编号：

```
6. 直播画面输出   编号：00
7. 音频输入信号(如有必要)   编号：06
```

### 第六步：设置「宿舍转发电脑」（仅操场直播需要）

这台电脑放在校园其他区域（一般建议放在非 12 栋以外的宿舍楼，网口需为 8 线全通〔22〕），专门负责把操场的画面"转一手"送到外网。**原则要求单显卡机型**，原因见【常见问题 2】。

在 OBS 里新建一个场景，再新建一个**媒体源**〔27〕：

![new1](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic7.jpg?raw=true)

![new2](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic8.jpg?raw=true)

取消勾选"本地文件"，在"输入"里填写地址（注意这是 **RTMP**〔7〕 协议格式），格式为：

`rtmp://室外路由器ip地址/livestream/直播画面输出的机位号`

（注意：下方截图里的地址填错了，正确格式应该是 `rtmp://10.58.3.161/livestream/*`）

![new3](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic9.png?raw=true)

回到 OBS 主界面，点一下"转场动画"〔28〕，如果能正常看到操场传来的画面，说明拉流成功。看不到的话，先看【常见问题 2】。接着点"设置"：

![new4](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic10.png?raw=true)

点"直播"，把从平台申请到的**推流地址和密钥**填进去。回到主界面，分别点"开始直播"和"开始录制"：

![new5](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic11.png?raw=true)

### 第七步：设置「现场切换电脑」（操场直播）

这台电脑在操场现场负责切换画面，可以和 SRS 是同一台，也可以分开。受性能限制，**建议至少 2 台电脑**。

> 提醒：这一步填的 IP 地址永远是 `192.168.31.*`（小米路由器的情况），也就是 SRS 服务器在局域网里的地址。**不再需要** `10.*.*.*` 开头的外网 IP。

1. 给每个机位建一个场景：用 USB 线或采集卡把相机接到电脑上，通过"视频采集设备"添加视频源。
2. 大疆设备（无人机、Pocket 等）不用采集卡：在 DJI Go 4、DJI Fly、DJI Mimo 等软件的"直播"选项里直接填推流地址，让大疆自己把画面推到 SRS，再用 OBS 的"媒体源"拉过来即可。
3. 切换画面：点"转场动画"，或拖动"快速转场"下面的滑轨。

![trans](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic12.png?raw=true)

**图层覆盖规则**：同一场景里，排在上方的图层会盖住下方的图层。想把多个画面混在一起时，记得把想显示的画面拖到上层。

**音频**：如果用了额外收音设备，或希望切换画面时声音不跟着切，请在右侧"混音器"〔29〕里调整各音源的开关和音量。

> 建议：一场直播尽量只用一个固定的声音来源，声音不随画面切换。优先用 DJI Mic（第二代）这类高质量收音设备，或直接用相机的收音。

**推流设置**：点"设置" → "直播"，填入平台推流地址和密钥，然后点"开始直播"和"开始录制"。码率可以在"设置" → "输出"里调整。

**关于码率**〔30〕：1080P 画面一般要 20M（20000K）以上的码率才清晰，但直播带宽往往扛不住。建议先设一个较高值（通常不超过 10000K），明显卡顿再往下调。**直播开始后尽量不要改动码率。** 2024 年 10 月迎新晚会最终用 4M（4000K）推送，有轻度卡顿。想要好画质，建议在机位旁另放一台相机全程录像兜底。大疆设备对高码率比较友好，一般不会严重卡顿。

### 第八步：直播录像转码〔33〕

OBS 录的直播回放默认是 mkv〔31〕格式，转成 mp4 便于分享：

```bash
ffmpeg -i 输入.mkv -c copy 输出.mp4
```

## 四.常见问题

### 1. 老师要求延迟推送〔37〕，出问题时要能及时切断，怎么办？

答：至少用 2 台笔记本电脑。把直播输出推给 SRS 服务器后，用第二台电脑拉取视频，在"设置 → 高级 → 直播延迟"里设置延迟时间。一旦出突发状况，在这个延迟缓冲的时间内，先登录微信视频号等平台后台关掉推流，再关闭其他设备，观众就来不及看到事故画面。

![SRS_Video](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic1.png?raw=true)

### 2. 一切配置好了，但 OBS 拉不到画面，怎么办？

答：这种问题多半出在**双显卡笔记本**上，单显卡电脑基本能避免。排查方法：在终端 / cmd 里跑 ffmpeg，命令格式是 `ffplay rtmp://*/livestream/*`。如果 ffmpeg 能正常播出来，就说明流本身没问题，是双显卡输出导致的兼容性 Bug。

- **临时方案**：用 ffmpeg 把视频全屏播放，再用 OBS 的"屏幕采集"把画面抓进来。

![ffmpeg](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic14.png?raw=true)

![can_not_read_video](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic2.png?raw=true)

- **根治方案**：开启显卡直连、关闭独立显卡，或者干脆换一台单显卡电脑。

### 3. SRS 报了这种错怎么办？

![srs](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic17.jpeg?raw=true)

**问题分析**：SRS 启动时会拉起好几个模块（RTMP、HTTP-FLV、WebRTC 等），每个模块都要占用一个端口〔24〕（常见的有 1935、1985、8080、8000、10080）。日志里出现 `errno=112` + `Address already in use`，意思是**端口被别的程序占用了**，SRS 抢不到。最常见的原因是开了多个 SRS 实例——检查一下托盘/后台，把多余的 SRS 全部关掉。

**如果还不行（Windows）**：在 cmd 里输入 `netstat -ano | findstr :xxxx`（xxxx 换成报错的端口号），会看到类似 `TCP    0.0.0.0:1935     0.0.0.0:0     LISTENING     1234` 的输出，最后一列数字就是占用端口的进程 PID。然后执行 `taskkill /PID 1234 /F`〔38〕 把它强制结束。仍无效就重启电脑。

### 4. SRS 刷了大量红色报错，但进程没停，怎么回事？

答：最常见的原因是**没有用管理员权限打开 SRS**。

### 5. 没有预览画面，OBS 一直提示"正在重连"，怎么办？

![obs](https://github.com/fang50253/NJFU_CS_Note/blob/main/Others/pic/live/pic18.jpeg?raw=true)

## 六.附录：0 基础也能看懂的专业名词

> 按在文中出现的顺序排列。正文中带 `〔n〕` 标记的词，都可以在这里查到。

**〔1〕SRS（Simple Realtime Server）**：一个开源的流媒体服务器软件。可以把它理解成一个"视频中转站"——别人把直播画面推给它，它再转给要看的人。在我们的方案里，它负责接收 OBS 推来的画面，供其他人拉取。

**〔2〕OBS Studio**：一款免费、开源的直播/录屏软件。负责把各路相机画面收集起来、切换镜头、加字幕，然后推流出去。我们所有现场操作（切画面、调音量、开推流）都在它里面完成。

**〔3〕推流（Push / Publishing）**：把直播画面"发送"出去的动作。就好比把水从水厂压进水管——推流就是"压水"的一端。

**〔4〕拉流（Pull / Playing）**：把已经推出去的直播画面"取回来"观看的动作。好比拧开家里的水龙头接水——拉流就是"接水"的一端。

**〔5〕二次转发**：由于操场电脑无法直接上外网，需要宿舍里的电脑先把画面从操场拉出来，再重新推到互联网直播平台。这种"先拉再推"的接力就叫二次转发。

**〔6〕局域网 / 校园网**：一个封闭的、互相联通的网络环境。路由器下面的所有设备（比如现场的几台电脑、相机）都在同一个局域网里，能互相访问但外界进不来。校园网则是整个学校范围的局域网络。

**〔7〕RTMP**：一种专门用于直播推流的传输协议（可以理解为"视频搬运的快递规则"）。我们的推流地址都是 `rtmp://...` 开头，就是走这种协议。

**〔8〕IP 地址**：每台联网设备在网内的"门牌号"。内网 IP（如 `192.168.31.*`）是路由器分配的，只在本局域网有效；外网 IP（如 `10.58.3.161`）用于让局域网以外的设备能找到它。

**〔9〕手动对焦（MF）**：相机不自动找焦点，由人拧对焦环固定焦点。直播时画面焦点固定，防止自动对焦来回"抽风"。

**〔10〕假电池**：外形像相机电池、实际连着外接电源的配件。插上它相机就一直有电，不用频繁换电池。

**〔11〕单显卡 / 双显卡**：单显卡电脑只有一个显示核心（核显或独显）；双显卡电脑有核显+独显两个。部分双显卡电脑在接收直播视频流时存在兼容性 Bug（见常见问题 2），所以推荐单显卡。

**〔12〕独显直连**：让独立显卡直接负责画面输出，绕开核显。支持独显直连的双显卡电脑可以规避上述 Bug。

**〔13〕全能本**：兼顾性能与便携的笔记本类型，通常性能释放比轻薄本强，又比游戏本轻便。一般只有核显或单 GPU，适合做直播机。

**〔14〕千兆 / 万兆网口**：指网口的最大传输速度（1Gbps / 10Gbps）。直播数据量大，网口越快越不容易卡。

**〔15〕APS-C 画幅**：相机传感器的一种尺寸规格。这类相机处理器散热压力较大，长时间录制可能因过热自动关机，所以要提前做压力测试。

**〔16〕采集卡**：一个把相机 HDMI 信号转成电脑能读的视频输入的小盒子。相机如果直接插电脑 USB 只能输出低画质，用"采集卡 + HDMI 线"能拿到 4K 全尺寸画面。

**〔17〕HDMI**：电视、显示器通用的高清音视频接口。相机上的 HDMI 口就是用来输出高清画面的。

**〔18〕4K**：一种超高清分辨率（3840×2160），清晰度约为 1080P 的四倍。

**〔19〕压力测试**：提前按实际使用强度连续运行设备（比如连续录 2~3 小时），确认它不会中途过热或死机。

**〔20〕环境变量 / Path**：系统记住的一些"全局设置"。把某个程序的目录加进 Path，之后在终端里直接输入程序名就能运行，不用写完整路径。

**〔21〕交换机**：校园网里的"分线器"，用来把一根网线分给多台设备、互通数据。操场看台下的网线就插在交换机上。

**〔22〕网口 8 线全通**：网线里有 8 根铜线。一般上网只用其中 4 根，但如果要做高带宽传输，需要 8 根全部接通。宿舍某些网口的 8 线是通的，适合做转发电脑的中继点。

**〔23〕OpenWRT**：一个开源的路由器操作系统，功能比原厂固件强，可以刷进小米等路由器里。本文用它的界面演示，与官方系统设置原理相同。

**〔24〕端口（Port）**：一台电脑上有无数个"服务入口"，端口就是给每个服务分配的编号。SRS 的各模块分别占用 1935、1985、8080、8000、10080 等端口。

**〔25〕端口转发**：把"外人请求访问路由器某端口"的流量，转交给内网某台电脑。这样外网才能连上我们内网的 SRS。

**〔26〕DMZ**：路由器的"全端口直通"模式——把内网某台电脑完全暴露给外网，所有端口都转发给它。没有特殊需求时，直播场景直接开 DMZ 最省事。

**〔27〕媒体源**：OBS 里的一种输入类型，可以播放网络上的视频/音频流。宿舍转发电脑就是用"媒体源"拉取操场 SRS 的画面。

**〔28〕转场动画**：OBS 里的"切换镜头"功能。点击它，主画面就从当前机位切到另一个机位。

**〔29〕混音器**：OBS 右侧的音量控制面板，可单独调节每个音源的音量、开关。

**〔30〕码率**：每秒传输的数据量（单位 Kbps 或 Mbps）。码率越高画面越清晰，但占用带宽越大；带宽不足就卡顿，所以要在清晰度和流畅度之间找平衡。

**〔31〕mkv / mp4**：两种视频封装格式。mkv 适合录制（容错性好），mp4 适合分享播放。OBS 录制默认 mkv，分享前用 ffmpeg 转成 mp4。

**〔32〕ffmpeg / ffplay**：命令行视频处理工具。`ffmpeg` 做转码、`ffplay` 播放/预览流。写好后缀参数能实现各种视频操作。

**〔33〕转码**：把一个视频的格式（或编码）转换成另一种，比如 mkv → mp4。

**〔34〕拓扑图**：用图形表示"谁连着谁"的网络结构图。文中的拓扑图展示了相机→OBS→SRS→路由器→校园网→宿舍转发→平台的整体链路。

**〔35〕DHCP**：路由器自动给接入设备发 IP 地址的机制。关闭某台路由器的 DHCP，它就只管"转发信号"而不再分配地址，地址统一由主路由器管理，避免冲突。

**〔36〕中继 Wi-Fi**：用一个辅助路由器把主路由器的 WiFi 信号"接力"转发出去，扩大无线覆盖范围。

**〔37〕延迟推送 / 直播延迟**：故意让观众看到的画面比现场晚若干秒。留出处置意外的时间差，避免把事故瞬间直播出去。

**〔38〕netstat / taskkill / PID**：都是 Windows 的命令行工具。`netstat -ano` 查看端口占用情况；PID 是每个进程的唯一编号；`taskkill /PID 编号 /F` 强制结束指定进程。

**〔39〕管理员权限**：Windows 下以最高权限运行程序。SRS 需要绑定系统端口、写系统设置，没管理员权限会报各种红色错误。

**〔40〕多路推流插件**：让 OBS 同时向多个平台推流的插件，比如 OBS 官方推荐的 RTMP 多路插件或第三方工具。
